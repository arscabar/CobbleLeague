# 전투 소환 복구 검사

`BattleRecoveryChecks.java`는 Cobblemon이 초기화된 별도 시험 서버용 결함 주입 검사입니다. 일반 JUnit 실행이나 운영 서버에 사용하지 않습니다. Minecraft 1.21.1 / Cobblemon 1.7.3 / CobbleLeague 0.7.2가 필요합니다.

서버 측 통합 시험 모드에서 이 파일을 컴파일하고 양쪽 파티의 소환이 실제로 시작한 `PokemonBattle`과 검사 결과 수집 콜백을 `BattleRecoveryChecks.run`에 넘깁니다. 최소 두 마리의 살아 있는 포켓몬을 가진 파티로 PvP와 PvE를 각각 실행합니다. 검사가 전투의 표현 상태를 바꾸므로 검사 직후 해당 시험 대전을 종료합니다.

검사 항목:

1. 활성 포켓몬 개체를 강제로 제거한 뒤 120틱의 유예가 지나면 같은 포켓몬을 다시 소환하는지 확인합니다.
2. 복구가 HP·활성 포켓몬 식별자·소유자 정보를 유지하는지 확인합니다.
3. 실제 Cobblemon 교체 처리를 호출하고, 회수 중인 개체를 제거합니다. 회수·소환 완료 처리가 복구되어 원래 `DispatchResult.canProceed()`가 참이 되는지 확인합니다. 턴 대기열을 강제로 건너뛰지 않습니다.

별도로 일반 전투, 강제 교체, 쓰러진 뒤 교체, 항복, 파티 복구를 확인해야 합니다. 이 검사는 렌더링 클라이언트를 모방하지 않으며 실제 게임 화면의 애니메이션·네트워크 검증을 대신하지 않습니다.


## 0.7.3 보상·재시작 회귀 검사

`CreepRoundSmoke.java`는 동일한 시험 모드에서 실행하는 Fabric 초기화 진입점(`ai.league.practice.CreepRoundSmoke`)입니다. Fabric API, Cobblemon, Kotlin과 Carpet의 가짜 플레이어 명령, 리그 본체·연습장·Run & Bun이 설치된 **폐기 가능한 서버**가 필요합니다. 실행 옵션 `-Dleague.smoke.enabled=true`를 주고 관리자 콘솔에서 `creepsmoke start`를 실행합니다. `creep-round-results.json`의 마지막 항목이 `completed`이고 모든 `passed`가 참인지 확인합니다.

실제 전투에서 PvP 양측 동의, 이전 시도의 요청 거부, 관장전에서 본인 전투만 재시작, 동시 상대 전투 보존, HP·돈·라운드 미정산을 확인합니다. 승리 보상의 돈 고정 + 두 가지 무작위 후보, 선택 전 미지급, 선택 전 확인 완료 거부, 하나만 지급 및 중복 요청 거부를 검사합니다. 환상·전설 등 특정 지급 경로를 빠짐없이 검사할 때는 시험 전용으로 후보를 고정하며, 실제 무작위 구성은 JUnit에서 여러 난수 시드로 검증합니다.

이 시험은 가짜 참가자를 생성하고 실제 임시 파티·게임 흐름을 조작합니다. 운영 서버나 보존해야 하는 월드에서 실행하지 않습니다. 친구용 설치 파일에는 포함하지 않습니다.
